# أداة فحص شبكة Wi-Fi (للقراءة فقط)

يجري السكربت `wifi-diag.sh` فحصاً فعلياً وشاملاً لشبكتك من حاسوب يعمل بنظام Linux، ومُعدّ أساساً لتوزيعة Fedora. يحفظ كل النتائج في ملف تقرير واحد، ويرتّب المشكلات حسب تأثيرها ويصنّفها إلى **مؤكدة** (CONFIRMED) و**محتملة** (POSSIBLE).

## الأمان: ما يفعله السكربت وما لا يفعله

| يفعل (قراءة وقياس فقط) | لا يفعل أبداً |
|---|---|
| يقرأ إعدادات الاتصال وقوة الإشارة | لا يغيّر أي إعداد في جهاز التوجيه أو في النظام |
| يرسل `ping` لاكتشاف الأجهزة وقياس زمن الاستجابة | لا يسجّل الدخول إلى جهاز التوجيه ولا يجرّب أي كلمة مرور |
| يطرح على جهاز التوجيه أسئلة UPnP للقراءة فقط (`Get…`) | لا يفصل أي جهاز ولا يعيد تشغيل Wi-Fi |
| يقيس السرعة عبر Cloudflare، ويستهلك نحو 140 ميغابايت | لا يحتاج إلى `sudo` |

## التشغيل على Fedora

1. **(اختياري، لكنه يضيف تفاصيل كثيرة)** ثبّت الأدوات الإضافية:
   ```bash
   sudo dnf install iw nmap mtr
   ```
   - `iw`: يعرض قوة الإشارة بالـ dBm، وسرعة الوصلة، وعرض القناة، وإعادة الإرسال، وتفاصيل جهاز التوجيه مثل WPS وTKIP وازدحام القناة.
   - `nmap`: يفحص المنافذ المفتوحة على جهاز التوجيه.
   - `mtr`: يتتبّع مسار الإنترنت ويقيس الفقد في كل قفزة.

2. ضع الملف `wifi-diag.sh` في أي مجلد، ثم افتح الطرفية (Terminal) في ذلك المجلد وشغّل:
   ```bash
   bash wifi-diag.sh --plan 100
   ```
   استبدل `100` بسرعة التنزيل في باقتك بالميغابت/ثانية. هذا الرقم يسمح للسكربت بأن يحكم هل تحصل على السرعة التي تدفع مقابلها.

   خيارات أخرى:
   - `--quick`: فحص أسرع، نحو دقيقتين بدلاً من خمس.
   - `--no-speedtest`: يتخطى اختبار السرعة إذا كانت باقتك محدودة البيانات.

3. **أثناء الفحص:** شغّل الحاسوب في المكان الذي تعاني فيه البطء عادةً، وأوقف التنزيلات والبث على هذا الحاسوب.

## كيف تعرف أن الفحص نجح؟

يكون آخر سطر في المخرجات بهذا الشكل:
```
Finished in 280 s. Report saved to: /home/<you>/…/wifi-report-20261122-2130.txt
```
وستجد الملف `wifi-report-….txt` في المجلد نفسه.

## أقسام التقرير

| القسم | ما الذي يقيسه |
|---|---|
| 2 | عنوان IP، وجهاز التوجيه، وخوادم DNS، وعقد DHCP، وإعدادات ملف الاتصال |
| 3 | قوة الإشارة واستقرارها، وسرعة الوصلة، وعرض القناة، ونسبة إعادة الإرسال، وتوفير الطاقة |
| 4 | الشبكات المجاورة، وازدحام كل قناة، وأفضل قناة متاحة، وتفاصيل جهاز التوجيه (WPS وTKIP ونسبة انشغال القناة) |
| 5 | طراز جهاز التوجيه، والمنافذ المفتوحة، وUPnP، وعنوان WAN (هل يوجد CGNAT أو Double NAT)، وحركة المنزل كله لحظياً |
| 6 | الأجهزة المتصلة: IP وMAC والشركة المصنّعة والاسم، والأجهزة غير المعروفة |
| 7 | زمن الاستجابة وفقد الحزم (إلى جهاز التوجيه وإلى الإنترنت)، وسرعة DNS، وMTU، وIPv6، والسرعة، وbufferbloat |
| 8 | التنزيلات التي تعمل في الخلفية على هذا الحاسوب |
| 9 | انقطاعات Wi-Fi المسجلة خلال آخر 24 ساعة وأسبابها |
| 10 | **الخلاصة: المشكلات مرتبة حسب التأثير** |

## مشكلات شائعة

- **`nmcli: command not found`**: نظامك لا يستخدم NetworkManager. سيعمل السكربت، لكن بتفاصيل أقل.
- **لا تظهر شبكات مجاورة**: انتظر دقيقة وأعد التشغيل، فـ NetworkManager يمنع تكرار المسح المتقارب.
- **قسم السجلات يقول "Cannot read system logs"**: هذا ليس خطأً. حسابك ليس في مجموعة `wheel`، ويمكن تجاهل الرسالة.

## الخصوصية

يحتوي التقرير على اسم شبكتك (SSID) وعناوين MAC وIP المحلية لأجهزتك. يُخفى الجزء الأخير من عنوانك العام (Public IP)، ولا تُجمع أي كلمة مرور. راجع التقرير قبل مشاركته إن أردت.

## ما لا يراه أي حاسوب

بعض المعلومات موجودة داخل صفحة إدارة جهاز التوجيه فقط: استهلاك كل جهاز للإنترنت، وإصدار البرنامج الثابت (Firmware)، وإعدادات QoS وDHCP، وإعدادات Wi-Fi لكل نطاق. صوّر هذه الصفحات بعد إخفاء كلمات المرور، وأرسل الصور مع التقرير لإكمال التحليل.
